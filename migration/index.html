    How to migrate from the old artnet_led integration?¶

    All your current fixtures are still supported! The integration can convert your old configuration for you, and your lights keep their entity IDs, so automations, scenes and groups keep working.

    Installing¶

    Our integration name changed from artnet_led to dmx. HACS doesn't allow this, so we are unable to upgrade this in-place. Therefore a manual release is needed for the beta.

    Under the release download the source code.

    In this ZIP, navigate to custom_components/dmx and copy this dmx folder into your Home Assistant's custom_components folder. Leave the old artnet_led folder where it is for now.

    Converting your configuration¶

    1. Add this line to your configuration.yaml:

      dmx: {}

      Home Assistant only loads the integration when dmx appears in your configuration.yaml; copying the folder or clicking Add integration won't load it. Write the {} too: a bare dmx: is empty and gets rejected as invalid configuration.

    2. Restart Home Assistant.

    3. Go to Settings → System → Repairs, open Old artnet_led configuration detected and submit it.

    The migration reads your old light: - platform: artnet_led configuration, including anything you pulled in through !include, !secret or packages, and writes two things into your config folder (the one that houses your configuration.yaml):

    • fixtures/: one Open Fixture Library fixture file for each distinct kind of light you had
    • dmx_migration.yaml: your new dmx: configuration, with the universes and devices of your old setup

    It doesn't change your configuration.yaml. If it shows migration notes, read them: they point out the few settings the new fixture format can't express, such as 32-bit channels or a colour temperature range on lights without a temperature channel.

    Switching over¶

    Do these steps in this order. Your old lights are still registered under their entity IDs; if the new ones show up before the old ones are deleted, Home Assistant gives them a _2 suffix instead.

    1. Remove the old light: - platform: artnet_led block from your configuration.yaml, keep dmx: {}, and restart.
    2. Under Settings → Devices & services → Entities, select your old lights, which now show as unavailable, and remove them.
    3. Replace dmx: {} with the contents of dmx_migration.yaml and restart.

    Your lights are now back under their old entity IDs. Anything you set on the old entities from the UI, like an area, icon or name, doesn't carry over, so set it again on the new ones.

    To tweak the result, like adding more fixtures or changing universes, see Configuration.

    Aftercare¶

    If the new light fixtures work, you may remove the old artnet_led folder and dmx_migration.yaml.

    When the 1.0.0 releases, this integration will be submitted for HACS default repositories, so manual installation won't be needed any more.

    Converting fixtures by hand¶

    You don't need this if the migration above worked. It's for when you'd rather use proper fixture definitions than the generated ones, for example to get the extra features of a fixture's manufacturer definition.

    Most of the previously supported fixtures already have a generic fixture variant for you to download.

    Download as: Open Fixture Library JSON

    Examples:

    • Single dimmer
    • CW/WW
    • Dimmer/color temperature
    • RGB
    • Dimmer/RGB
    • RGBWW

    This downloads a ZIP, inside this ZIP ignore the manufacturers.json and copy the JSON file of fixture itself into your HomeAssistants config/fixtures folder, which you will need to create.

    This fixture format is extremely flexible and contains templating, channel switching, matrixes, and many other crazy things, and we're compatible with all of it. :)

    You can go ahead and use the editor or write a JSON by hand.

    Note down the shortName of your fixtures, or name if it has no shortName, then add them to your house as explained in Configuration.
